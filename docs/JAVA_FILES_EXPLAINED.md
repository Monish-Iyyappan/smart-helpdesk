## 14. Concepts NOT Used Anywhere in the Codebase

To prevent students from incorrectly claiming concepts during a code defense or presentation, the following OOP and Java language features were verified to be **completely absent** from this codebase:

1. **Interface Inheritance (`interface X extends Y`)**:
   - No custom interface extends another interface. Interfaces implemented (`UserDetails`, `ApplicationRunner`, `RowMapper`) come directly from Spring or standard libraries.
2. **Explicit Interface Declarations for Services/DAOs**:
   - Services (`TicketService`, `AdminService`, `IncidentService`) and DAOs (`TicketDAO`, `UserDAO`) are implemented directly as concrete classes without separating into `TicketServiceImpl implements TicketService` interfaces.
3. **Method Hiding (Static method hiding in subclasses)**:
   - No subclass re-declares a static method from a parent class.
4. **Multiple Inheritance of Type (Multiple interfaces on a single class)**:
   - No class implements multiple interfaces simultaneously.
5. **Thread Synchronization Primitives (`synchronized`, `volatile`, `wait()`, `notify()`):**
   - Concurrency is managed at the HTTP servlet / Spring container layer; there are no manual thread locks, synchronized blocks, or volatile variables.
6. **Explicit Multithreading (`Thread`, `Runnable`, `ExecutorService`)**:
   - The application does not instantiate `new Thread()` or manage custom thread pools directly.
7. **Java Reflection API (`java.lang.reflect.*`)**:
   - No custom runtime reflection code is written (reflection is handled purely internally by Spring framework annotations).
8. **Checked Exceptions (`extends Exception`)**:
   - All custom exceptions (`AssignmentException`, `ResourceNotFoundException`) inherit from `RuntimeException` (Unchecked exceptions).
9. **Design Patterns NOT Present**:
   - **No Factory Pattern classes** (only static factory methods like `UserResponse.from(...)` are used).
   - **No Singleton class using classic `getInstance()`** (singletons are managed via Spring IoC container bean lifecycle).
   - **No Observer Pattern / Event Listeners** (e.g., no `ApplicationEventPublisher` or `@EventListener`).
